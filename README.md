# AI量化策略可视化平台

本项目是一个基于 Python (FastAPI) 和 React (Vite + Ant Design) 的量化交易策略回测平台。

## 项目结构

- `server/`: 后端代码
  - `core/`: 核心回测逻辑 (Backtrader 封装)
  - `main.py`: FastAPI 接口服务
- `web/`: 前端代码 (React)
  - `src/App.jsx`: 主界面逻辑

## 启动方式

### Windows 一键启动

双击项目根目录的 **`start.bat`**，即可启动前后端并自动打开 `http://127.0.0.1:5173`。窗口关闭后服务继续在后台运行，重复双击会复用已运行的本项目服务。

- 电脑需要先安装 Python 和 Node.js（本项目已验证 Python 3.13、Node.js 22），安装后重新打开脚本。
- 首次运行自动创建 `.venv`，缺少依赖时自动安装；首次安装需要联网，可能需要几分钟。
- 没有 `.env` 时会从 `.env.example` 创建，请填写天勤账号和金十 Token 后使用相应数据源；已有配置不会被覆盖。
- 固定使用后端 `8000`、前端 `5173` 端口，其他程序占用时会提示退出。
- 启动日志位于 `.venv/run/`。命令行运行 `start.bat -NoBrowser` 可不打开浏览器；依赖需要重新安装时，先停止服务，再运行 `start.bat -InstallDependencies`。

### 1. 启动后端服务

打开终端，进入项目根目录：

```bash
# 安装依赖
pip install -r server/requirements.txt

# 启动服务
python server/main.py
```

服务将在 `http://localhost:8000` 启动。

### 天勤 TqSdk 免费行情

回测页和明日策略页新增“行情供应商”，可在原有来源和“天勤 TqSdk 免费版”间切换。
“合约口径”单独选择主力连续或加权指数。天勤免费版在本平台仅接入期货。

1. 在 [快期用户中心](https://account.shinnytech.com/) 注册普通快期账号；本接入只读取行情，不需要期货交易账户。
2. 安装更新后的后端依赖：`pip install -r server/requirements.txt`。
3. 复制根目录 `.env.example` 为 `.env`，在本机填写 `TQ_USERNAME` 和 `TQ_PASSWORD`。`.env` 已被 Git 忽略；不要把凭据提交到仓库或粘贴到聊天中。也可通过同名环境变量配置，环境变量优先。
4. 在界面选择“天勤 TqSdk 免费版”。配置在下次请求时读取，无需重启；状态提示会在切换供应商或刷新页面时更新。

本接入只调用免费滚动序列 `get_kline_serial`，每次最多 10000 根，**没有调用专业版历史下载接口**。
实际覆盖时间依品种、周期和账户权限而定；没有选择日期时使用可返回的近期窗口，超出窗口的日期请求会明确报错，不会更换供应商、合约口径或周期。
自动优化和明日策略详情沿用所选供应商；结果和手动保存的历史记录包含实际来源、天勤合约代码和数据起止时间。

时间统一转换为北京时间。分钟线按 K 线起点加周期判断完成；日线保守地以对应日期 15:15 为完成界限，盘中不使用当日未结束日线。
分钟线日期筛选按北京时间自然日，夜盘以图中实际时间显示。开始日期最多容许 5 个自然日的休市间隔；更大的覆盖缺口会拒绝回测。

验证命令：`python -m unittest discover -s tests -v`，前端 `cd web` 后运行 `npm run build`。
尚未配置账号时可以验证配置提示和测试；真实行情连接需要在本地填写有效凭据后验证。

### 2. 启动前端界面

打开新的终端，进入 `web` 目录：

```bash
cd web

# 安装依赖 (如果尚未安装)
npm install

# 启动开发服务器
npm run dev
```

浏览器访问显示的地址 (通常是 `http://localhost:5173`)。

## 功能特性

- **切换页面继续回测**：在同一浏览器标签页内切换侧边栏，单品种、多品种和多合约回测队列均继续执行；请求、真实进度和结果由全局任务保存。返回回测页时恢复执行进度或已完成的图表、交易记录与失败信息，并保留提交的配置和自动优化选项。任务运行期间禁止重复启动；其他页面顶部显示回测进度或完成状态，可点击返回查看，离开期间完成也会收到提示。
- **合约行情本地数据库**：回测具体合约时，先检查 `server/market_cache.sqlite3` 中对应供应商、合约及周期的已完成行情和覆盖区间，覆盖不足才请求第三方，再保存本次返回的完整可用序列，供后续回测和指标预热复用。历史 K 线去重且不覆盖；周线复用日线后合成。只按回测需求下载，不预拉所有品种，不持久化主连、加权指数、股票行情或实时报价。未完成 K 线及未来区间不标记为已有覆盖，进行中的合约会按需补充新行情；第三方滚动窗口无法补齐的缺口明确报错。回测结果标注本地命中、首次获取或覆盖不足补充。数据库自动创建并被 Git 忽略，服务重启后仍可复用。
- **品种列表缓存**：`/api/symbols` 在本地缓存期货列表 24 小时、股票列表 6 小时；`/api/futures/contracts` 按品种缓存真实合约列表 1 小时。缓存过期后在下一次请求时更新，更新失败优先返回上次成功的列表并在 60 秒后重试；首次股票取数失败的备用列表也仅缓存 60 秒，避免故障结果长期占用缓存。
- **具体合约回测**：策略回测在“交易品种”下提供“具体合约（可多选）”，单选期货品种后从天勤读取实际合约列表（含已到期合约）。每个所选合约独立生成回测结果，逐个展示成败、图表与统计，并可分别保存。各合约时间范围独立锁定：从交割月往前第 5 个月的 1 日，到交割前一个月的 23 日（含当天），跨年时同步调整年份。2605 为 2025-12-01 至 2026-04-23，2701 为 2026-08-01 至 2026-12-23；多选时不会合并日期范围。回测、优化和保存均保留具体合约及该时间范围；只使用已经产生的行情，没有数据时明确报错。免费分钟线窗口不能覆盖所选范围时不会改用主连。清空全部合约后恢复普通品种回测及手动日期选择。
- **20/55 单方向策略**：新增“20/55双均线交叉多（只做多）”和“20/55双均线交叉空（只做空）”。多头版空仓时金叉开多、持有多单时死叉平仓；空头版空仓时死叉开空、持有空单时金叉平仓。均不加仓、不反手，离场后等待新的同方向交叉信号，默认 MA20/MA55、固定手数，支持开平仓 K 线延迟和回测末尾平仓。策略回测、明日策略和品种扫描均可选择。

- **明日策略**：列表和详情共用策略执行逻辑，保留当前持仓，不在数据末尾强制平仓。详情固定使用分析时的策略、参数、行情口径及历史起止时间；旧行情起点已滚出免费窗口时要求重新分析。默认显示最近 200 根及当前持仓的开仓区间，并可展开真实交易记录。均线直接读取已执行策略的指标，包括默认周期和 EMA；最新 K 线的未成交市价信号单独提示，等待下一根 K 线成交。止盈和止损使用互斥订单，防止同一根 K 线重复平仓；同根同时触及时按止损优先模拟。当前支持固定手数，不再提供策略尚未实现的资金比例、ATR仓位及中间价执行选项。

- **K线对比**：侧边栏最下方进入，默认天勤期货数据。选择 10～500 根同周期 K 线，可指定基准结束时间和历史搜索范围，按开高低收的标准化形态距离查找相似片段。排名结果互不重叠，历史片段及后续观察区间均早于基准；点击结果查看叠加曲线和两组 K 线。相似度为形态分数，不是上涨概率。只在实际可获取的最近最多 10000 根数据内搜索；原有来源在此功能中仅支持主力连续日线，避免分钟或指数数据被静默替换。

- **策略配置**：支持动态调整均线周期、ATR止损倍数、风险系数等。
- **回测计算口径（v2）**：行情参考价格直接使用数据源最近报价，不叠加保证金率，也不参与历史成交价计算。合约价值为价格 × 乘数；理论可开手数按保证金及估算开仓手续费计算。期货按开仓均价冻结保证金、按 K 线盯市结算盈亏；股票按每手股数乘数和全额资金记账。开平仓手续费统一暂按成交名义金额的 0.01% / 边估算，未计滑点，未模拟保证金率调整或强平；保证金不足的开仓会被拒绝。权益曲线直接记录每根 K 线的实际账户权益，最大回撤按收盘权益（含浮动盈亏）及初始资金计算。夏普只使用所选日期窗口内的账户收益，分钟线按日聚合、日线年化因子 252、周线 52，无风险利率为 0，数据不足时留空。交易次数与胜率仅计完整已平仓交易，持平交易单列；单手累计净利只在交易结算时统计一次，按每笔累计开仓手数折算，单手累计收益率按开仓名义金额（含乘数）计算后求和，不等于账户收益率或复利收益率。新结果标记 `calculation_version=2`，旧历史结果不自动改写，需重新回测。
- **开平仓 K 线设置**：策略回测的“开仓 K 线”“平仓 K 线”分别设置市价信号单在触发后的第几根 K 线开盘成交，均默认为 1（下一根），填 2 为第二根。按实际 K 线计数，跳过休市间隔；等待期间保留原订单，不重复提交。反手属于合并开平仓订单，采用两者较大值；止盈止损挂单仍按触价规则执行。末尾未等到执行时间的订单不生成成交，平台强制平仓不受延迟限制。设置随单品种、批量回测与保存记录传递，延迟成交日志与交易记录保留信号时间及根数。
- **20/144 金叉多头策略**：在策略回测中选择“20/144金叉做多·20/55死叉离场”。空仓时只在 MA20 上穿 MA144 当根发出做多信号，持仓时只在 MA20 下穿 MA55 时离场，不加仓、不做空；离场后必须等待新的 MA20/144 金叉，持续位于 MA144 上方或单独出现 MA20/55 金叉均不会重新入场。使用固定手数，均线按当前周期计算，至少需要 145 根有效 K 线确认交叉。默认收盘确认信号、下一根开盘成交，回测结束沿用平台统一平仓规则。
- **20/144 死叉空头策略**：选择“20/144死叉做空·20/55金叉离场”。空仓时只在 MA20 下穿 MA144 时做空，持仓时 MA20 上穿 MA55 平空；不加仓、不做多，离场后必须等待新的 MA20/144 死叉，持续位于 MA144 下方或单独出现 MA20/55 死叉不会重新开仓。沿用固定手数、三条均线、至少 145 根历史、开平仓 K 线延迟及回测末尾平仓规则。
- **20/144 多空合并策略**：选择“20/144多空入场·20/55交叉离场”。空仓时 MA20 上穿 MA144 做多、下穿 MA144 做空；多单在 MA20 下穿 MA55 时平仓，空单在 MA20 上穿 MA55 时平仓。一次只持有一个方向，不加仓、不直接反手；持仓期间只处理离场信号，同根 K 线同时出现离场和反向入场交叉时只离场，平仓成交后等待新的 MA20/144 交叉。沿用固定手数、MA20/55/144 图表、开平仓 K 线延迟及回测末尾平仓规则。
- **20/144 同均线离场三个策略**：新增“20/144多空入场·20/144交叉离场（反手）”、只做多和只做空版本。入场和离场均使用 MA20 / MA144：只做多在金叉开多、死叉平多；只做空在死叉开空、金叉平空；多空版空仓时按交叉方向入场，持有多单遇死叉时平多开空，持有空单遇金叉时平空开多。反手后保持设定的固定手数，不加仓；反手合并为一个目标仓位订单，执行延迟取开仓和平仓 K 线设置的较大值。保留原先 20/55 离场版本；支持固定手数、开平仓 K 线延迟、末尾平仓和至少 145 根历史检查。回测、明日策略和品种扫描均可选择。
- **后续逐根详情**：K 线对比的历史排名每行提供“详情”，展示后续每根 K 线的时间、开收盘、前收、本根收减开、较前收涨跌额/幅及累计涨跌额/幅。第一根以前述历史匹配末根收盘为前收，累计始终以该收盘为基准；沿用本次查询的后续观察根数，超过 20 根时分页。数据直接使用已返回的历史 K 线，缺失价格留空，零观察根数时显示空状态，不额外请求行情。
- **原油与白银行情栏**：近期消息页面顶部显示金十 MCP 的布伦特 `UKOIL`、WTI `USOIL` 与现货白银 `XAGUSD` 最新报价、涨跌额/幅、今开/最高/最低/成交量，以及北京时间的报价和获取时间。先读取 `quote://codes` 确认品种，再调用 `get_quote({code})`。原油单位为美元/桶，白银单位为美元/盎司。页面可见时每 4 分钟更新，可手动刷新；后端 60 秒共享缓存以节省各工具每日额度。三个品种独立处理错误，更新失败时明确显示上次价格和原时间；超过 15 分钟的源报价标注较早，便于识别休市或延迟。行情栏独立于新闻来源切换。
- **近期消息**：侧栏进入 `/recent-news`，中东、美国、原油三个板块支持自动外网优先、国内优先金十、仅金十、东方财富与 Google 新闻 RSS。默认先 Google，失败的板块回退到金十及东方财富；国内模式优先金十，未覆盖的历史由东方财富补充。按滚动 72 小时筛选并倒序展示，每板块最多 100 条、每页 10 条；时间均为北京时间。页面可见时每 5 分钟更新，手动刷新绕过五分钟缓存。各源缓存隔离，取数失败和历史未取全均有提示，逐条保留来源与原文链接。
- **金十官方 MCP**：在 Git 忽略的根目录 `.env` 中配置 `JIN10_MCP_TOKEN`，后端直接以 Bearer Token 访问 `https://mcp.jin10.com/mcp`，不向浏览器下发凭证；无 Token 时使用公开快讯。流程为 `initialize` → `notifications/initialized` → `tools/list` / `resources/list` → `tools/call`，推荐协议 `2025-11-25`，支持 JSON 与 SSE 响应、会话头及版本协商。工具机器数据只读取 `structuredContent`，业务列表只用 `cursor / data.next_cursor / data.has_more` 分页；JSON-RPC 错误和工具业务错误分开处理。8 个工具与 `quote://codes` 通过运行时发现，可由后端 `Jin10MCPClient` 调用；本次页面使用 `list_flash`。最近 72 小时数据和历史续传游标保存在 Git 忽略的 `.venv/jin10_mcp_news.json`，按增量更新；工具用量按北京时间自然日、各工具分别记录在 `.venv/jin10_mcp_usage.json`，本地 1440 次后停止，为服务端 1500 次上限预留余量，实际剩余额度仍以服务端为准。`/api/news/jin10/status` 仅返回配置及连接状态。接口未提供足够三天历史时如实提示，国内模式可使用东方财富补充。
- **均线辅助对比**：K 线对比可单选或多选 MA20、MA60、MA144；不选时沿用 K 线形态评分。选择后 K 线占评分的 50%，所选均线合计占 50%且等权，比较均线形态与价格相对位置，并在形态叠加及两组 K 线图中显示所选均线。历史预热不足的窗口不参与排名，后续观察数据不参与评分。
- **均线显示**：回测、回测记录、明日策略详情及 K 线对比均支持 MA144，可通过图例显示或隐藏。按当前 K 线周期计算，日线下为 144 日均线；新结果使用可用历史预热，旧记录从保存的 K 线补算，未满 144 根时留空。
- **多品种支持**：支持生猪、烧碱、螺纹钢等期货品种。
- **可视化回测**：展示账户权益曲线和关键绩效指标 (Sharpe, Drawdown, Win Rate)。
- **指标计算**：
  - **一手盈利百分数**：计算公式为 `每手累计净利润 / 平均开仓价格`，反映账户相对于平均开仓成本的总收益率。
  - **一手最终赚钱数**：反映扣除佣金后的每手累计净利润。
- **交易日志**：详细记录每笔交易的执行情况，包括收益率统计。
- **回测历史看板**：支持按策略、品种、盈亏、保存日期与关键词筛选，同步展示记录概览、收益排名及收益/回撤散点图；点击图表进入详情。勾选 2～4 条记录可对比按各自初始资金归一化的权益曲线，保留详情、参数、日志与删除入口。收益率优先从净利和初始权益推导，胜率及回撤按 0～100 百分数展示，不重复乘 100；平均单次收益率不视为投资组合收益。
- **交易日志看板**：可切换当前回测和已保存记录，刷新后无当前回测时自动载入最近的历史日志。提供成交/结算统计、累计结算净利曲线、事件分布、明细表与最新 40 条事件时间线；支持品种、事件、日期和关键词联动筛选，并导出当前范围 CSV。盈亏只累加交易结算日志，避免与平仓成交估算重复计数，不含未平仓浮盈亏；缺失数据留空。
